# Backend — обзор

Бэкенд лежит в `backend/` и им владеет отдельный разработчик (Егор). **Фронтенд-агент код здесь не пишет и не меняет без явной просьбы пользователя** — этот файл нужен ему только чтобы понимать, с чем интегрируется, и не проектировать контракт вслепую.

Если ты пишешь бэкенд — тебе сюда: [**architecture.md**](architecture.md). Там слои, паттерн Repository + Interface, SOLID применительно к этому коду, структура каталогов и скелеты для копирования.

## Стек

- FastAPI, асинхронный
- Pydantic v2 — валидация и схемы
- PostgreSQL + SQLAlchemy 2.0 (async) + Alembic — миграции
- Redis
- Arq — очередь задач

## Архитектура в двух словах

Модульный монолит с чётким разделением по доменам — расчёт на то, чтобы при росте можно было безболезненно выделить отдельные сервисы. Тяжёлые операции (генерация приложения по промпту, сборка zip) идут через очередь и не блокируют HTTP-запрос.

`AppDocument` целиком хранится как `JSONB` в колонке `document` таблицы `apps` — отдельных таблиц под экраны и узлы нет, документ гоняется целиком. Форма документа — общий контракт с фронтом: [`../product.md`](../product.md#модель-данных) и [`../api-contract.md`](../api-contract.md).

## Что не специфицировано

Протокол чата с ассистентом, загрузка файлов, авторизация, способ генерации документа из промпта — решается вместе с Егором по ходу разработки, не додумывается фронтом в одиночку. Подробности и текущее состояние каждого вопроса — в [architecture.md](architecture.md#14-что-ещё-не-решено).
