# Feature-Sliced Design — правила для `apps/web`

FSD применяется внутри `frontend/apps/web/src`. `frontend/packages/api` — не ФСД-слой, это внешняя основа под всеми слоями (см. [overview.md](overview.md)).

## Слои, сверху вниз

```
app → pages → widgets → features → entities → shared
```

Правило одно и неизменное: **слой может импортировать только из слоёв строго ниже себя.** Не из соседних слайсов своего слоя, не сверху. `shared` не знает ни о чём, `entities` не знает про `features`/`widgets`/`pages`, и так далее. Слоя `processes` нет (устарел в FSD, не создавай).

- **`app`** — точка входа, провайдеры (`QueryClientProvider`, роутер), глобальные стили и CSS-переменные дизайн-системы (`app/styles/tokens.css`), инициализация `packages/api`-клиента.
- **`pages`** — компоненты роутов: `HomePage`, `AppsListPage`, `EditorPage`, `PublicPreviewPage`. Роутинг через React Router, конфиг живёт в `app/router.tsx` и импортирует эти компоненты. Тонкие — собирают виджеты, сами логики почти не содержат.
- **`widgets`** — самостоятельные композитные блоки редактора. Что уже есть: `editor-header` (шапка + бейдж сохранения), `assistant` (колонка чата, включая свёрнутую полосу), `files-panel`, `code-panel`, `canvas` (`Board` + `PhonePreview` + `Canvas` + `BoardToolbar`), `inspector`, `insert-dock`.
- **`features`** — конкретное пользовательское действие, у которого есть глагол. Что уже есть: `create-app-from-prompt` (карточка промпта + AI-интервью), `refine-app-from-chat` (regex-парсер команд, патчащий стор), `autosave-app-document` (дебаунс 1200мс + `flush`). Одна фича — одно действие, не «раздел UI».
- **`entities`** — бизнес-сущности продукта со своим отображением. Два разных `app*`-слайса, не путать: `entities/app` — карточка приложения в списке `/apps` (обёртка над `AppSummary` из `packages/api`); `entities/app-document` — состояние редактируемого документа: Zustand+Immer стор (`useAppDocumentStore`) плюс `lib/codegen.ts` (`AppDocument` → файлы Expo-проекта, чистая функция). Стор держит не только сам документ, но и выделение/историю/буфер обмена — это осознанно один стор на весь редактор, а не россыпь маленьких, потому что канвас/инспектор/AI-док правят один и тот же документ и должны видеть согласованное состояние.
- **`shared`** — UI-кит по дизайн-системе (`shared/ui`: `Button`, `ColorPicker`, `NumberField`, `AlignPad`, `BildoLogo`), обёртка над `packages/api` (`shared/api`), вложения (`shared/attachments`), хуки и утилиты (`shared/lib`: `useWindowEvent`, `useOutsideClick`, `buildFileTree`), конфиг маршрутов (`shared/config`).

## Сегменты внутри слайса

Каждый слайс (`widgets/canvas`, `features/send-chat-message`, `entities/screen`...) может иметь сегменты: `ui/`, `model/`, `api/`, `lib/`, `config/`. Не создавай сегмент, который пуст — если у фичи нет своего `api`, потому что она работает только с локальным Zustand-стором, сегмента `api/` не будет.

## Публичный API слайса

Импортировать слайс — всегда через его `index.ts` (barrel export), никогда напрямую во внутренний файл (`widgets/canvas/ui/Canvas.tsx` — нет, `widgets/canvas` — да). Это единственное, что защищает от циклических зависимостей и протекания деталей реализации между слайсами.

## Стили

**CSS Modules** (`Component.module.css` рядом с компонентом) + CSS-переменные дизайн-системы из `app/styles/tokens.css`. Хардкод цветов в компонентах не пишем — только токены (`var(--color-accent)` и т.д.).

Инлайн-стили — только для по-настоящему динамических величин, которые невозможно выразить классом: позиция узла на канвасе, трансформ доски, цвет из темы пользовательского приложения. Ховеры/фокусы/активные состояния всегда через CSS, а не через `onMouseEnter` с мутацией `e.currentTarget.style` (так было в прототипе — при переносе исправлено).

Не смешивай сокращённые и полные CSS-свойства для одной величины (`padding` и `paddingBottom` одновременно) — явное требование дизайн-системы, результат непредсказуем. В `Canvas` для этого есть `resolvePadding`.

Стили содержимого превью пользовательского приложения (`app/styles/app-content.css`, классы `app-anim--*`) — отдельный, изолированный набор: токены интерфейса Bildo внутрь рамки телефона не протекают.
