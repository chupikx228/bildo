# Продукт

Источник: ТЗ заказчика (Bildo.docx) + макеты с аннотациями. Ниже — выжимка, актуальная на старт разработки.

## Что делаем

Веб-редактор для создания мобильных приложений. Пользователь описывает идею словами, система собирает готовое приложение из экранов, дальше он правит его визуально на бесконечной доске или через чат с ассистентом, смотрит превью, делится ссылкой и выкладывает в общий/локальный доступ.

## Модель данных

Всё приложение пользователя — один JSON-документ `AppDocument`, который на бэкенде лежит в таблице `apps` в колонке `document`. Это контракт между фронтом и бэком — детали типов см. [api-contract.md](api-contract.md).

Верхний уровень `AppDocument`:
- `name`, `id`, `prompt`, `revision`, `createdAt`, `updatedAt`
- `theme` — 10 токенов: фон, поверхность, граница, текст, приглушённый текст, акцент, текст на акценте, базовый радиус, шрифт текста, шрифт заголовков
- `navigation` — тип (`tabs` / `stack` / `drawer`) и список корневых маршрутов
- `screens[]` — у каждого экрана `id`, `name`, `route`, `root` (корневой узел)
- `state` — переменные приложения (строки, числа, булевы)

Узел (`AppNode`) — элемент на экране: `type`, `props`, `style`, `layout`, `children`, флаги `hidden`/`locked`.

Восемь типов узлов: `View` (контейнер), `Text`, `Button`, `Image`, `TextInput`, `ScrollView`, `FlatList`, `Spacer`.

Позиционирование абсолютное: `x`, `y`, `width`, `height`, опционально `zIndex`. Логическая сцена экрана — **370 × 640** точек, всё внутри рамки телефона считается в этих координатах.

Стили узла: направление и выравнивание флекса, зазор, отступы, цвет фона, градиент, цвет текста, размер и вес шрифта, выравнивание текста, межбуквенное, интерлиньяж, радиус, толщина и цвет рамки, тень, ширина/высота, прозрачность, фоновая анимация (`float`, `pulse`, `breathe`, `shimmer`, `rise`, `drift`).

Интерактив: у узла есть `onPress` и `onChange` — массивы действий. Действий четыре: `navigate` (перейти на маршрут), `setVar` (записать переменную), `toast` (показать уведомление), `openUrl`. Текст можно привязать к переменной через `textBind`, значение поля ввода — через `valueBind`.

**Важно:** стили интерфейса самого Bildo и стили генерируемого пользователем приложения — два полностью изолированных набора. Токены дизайн-системы Bildo (см. [design-system.md](design-system.md)) не имеют отношения к теме генерируемого приложения (10 токенов выше) — это разные системы координат.

## Экраны продукта

### 3.1 Главная `/`
Логотип, ссылка «Мои приложения», крупная карточка ввода промпта (многострочное поле, отправка Enter или кнопкой «Создать приложение», активна от 3 символов). Слева от кнопки отправки — скрепка с меню: загрузить изображения, загрузить файлы, переключатель Plan mode. Вложения и включённый Plan mode — чипы над строкой действий, снимаются крестиком.

Под карточкой — 3-4 моковых примера запроса (клик сразу создаёт приложение).

Ниже — вход в AI-интервью («Ответьте на 5 вопросов»): карточка ввода заменяется карточкой интервью на том же месте. 5 шагов (тип приложения, аудитория, нужные экраны — мультивыбор, настроение, важные детали — варианты + свободный ввод), одиночный выбор автолистает вперёд, полоски прогресса сверху кликабельны для возврата. Последний шаг показывает собранный промпт текстом, редактируемым, можно добавить файлы — и только потом «Создать приложение» (тот же эндпоинт, что обычный промпт). После отправки юзера сразу бросает в редактор.

### 3.2 Список приложений `/apps`
Карточки: имя, дата обновления, переход в редактор, удаление с подтверждением. Кнопка «Новое» → главная.

### 3.3 Редактор `/editor/[id]`
Четыре колонки под общей шапкой: **чат ассистента** / **файлы** / **доска** / **инспектор**. Ширина чата и файлов — CSS-переменные, обе колонки сворачиваются (доска никогда не перекрывается интерфейсом — колонки меняют ширину сетки, не накладываются).

**Шапка.** Логотип, ссылка «Приложения», имя приложения (правится на месте) + бейдж статуса сохранения; кнопки «Файлы»/«Код» (переключатели с активным состоянием); «Превью»/«Остановить»; «Поделиться»; «Экспорт».

**Чат ассистента** (левая колонка). История сообщений, индикатор набора, карточки предложений и коммитов. Каждое изменение документа приходит как предложение с описанием, списком затронутых файлов и сводкой диффа — пользователь принимает/отклоняет, принятое пишется в историю как коммит. Ввод: Enter — отправка, Shift+Enter — перенос строки. Скрепка справа от кнопки отправки — загрузка изображений/файлов. Колонка сворачивается в узкую полосу со счётчиком неподтверждённых предложений.

**Файлы** (вторая колонка). Дерево сгенерированного проекта — строится тем же генератором, что и экспорт (всегда совпадает со скачиваемым архивом). Поиск по путям, сворачивание папок, размер файла, цвет иконки по расширению, клик открывает просмотр кода. Отдельная группа «Мои файлы» — загрузка кнопкой или drag&drop, удаление крестиком.

**Доска** (центр). Экраны приложения — рамки телефонов рядом. Панорамирование колесом/перетаскиванием пустого места/пробел+ЛКМ/средняя кнопка; зум Ctrl/⌘+колесо. Имя экрана правится на месте, есть удаление по наведению, плитка «Новый экран». Внутри активной рамки — выделение и правка узлов: клик выбирает, рамка с ручками ресайза, drag мышью, стрелки — сдвиг на 1px. Плавающий док вставки внизу по центру: 5 частых элементов + кнопка «Элемент» с палитрой поиска по всем типам; видно, куда попадёт элемент (выбранный контейнер → его родитель → корень экрана). В режиме превью док скрыт.

**Инспектор** (правая колонка), без вкладок — всегда свойства текущего выделения:
- ничего не выбрано → свойства всего приложения (имя, тема — 10 токенов)
- выбран экран → «Содержание» (текст, плейсхолдер, ссылка на картинку, имя слоя, скрытие, блокировка), «Позиция» (блок выравнивания 9 позиций + X/Y/W/H), «Внешний вид» (заливка, цвет текста, шрифт, выравнивание, радиус, отступы, прозрачность, рамка), «Поведение» (действие на нажатие: переход, запись переменной, уведомление, ссылка — пока неактивно)

**Просмотр кода.** Кнопка «Код» или клик по файлу. Занимает область доски (не всё окно). Путь крошками, номера строк, подсветка синтаксиса, счётчик строк/размера, копирование, быстрые переходы к `app/index.tsx`, `app/_layout.tsx`, `package.json`. Только чтение, Esc закрывает.

**Режим превью.** «Превью» снимает выделение, делает содержимое рамки интерактивным (нажатия, переходы, переменные, тосты реально работают). Повторное нажатие — обратно в режим правки.

**Горячие клавиши.** Ctrl+Z/Ctrl+Y — отмена/повтор, Ctrl+D — дублировать, Ctrl+C/Ctrl+V — копировать/вставить, Delete/Backspace — удалить.

### 3.4 Публичное превью `/p/[id]`
Рамка телефона с работающим приложением, без редактора. «Поделиться» в редакторе копирует эту ссылку в буфер.

## Сохранение и история

Автосохранение: любое изменение → статус «не сохранено» → через 1200 мс `PUT`. Статусы: сохранено / сохранение / не сохранено / ошибка. Перед экспортом документ принудительно досохраняется. Документ несёт `revision` — сервер принимает `PUT` только с актуальной ревизией и отвечает 412 на устаревшую (оптимистичная блокировка, см. [api-contract.md](api-contract.md#оптимистичная-блокировка--revision-bil-46)); разбор конфликта в интерфейсе — BIL-47.

История — два стека (назад/вперёд) со снимками документа и подписью действия, в состоянии клиента (не на сервере). Drag и ресайз склеиваются в одну запись истории (не откатывать по пикселю). Изменение от ассистента — один шаг истории целиком.

## Открытые вопросы (не описаны в ТЗ, решать при реализации)

- ~~Протокол чата с ассистентом (SSE/WebSocket/поллинг)~~ — закрыто в BIL-36 (история и решения) и BIL-37 (разговор с LLM): выбран **поллинг**, `POST .../chat/messages` отдаёт `taskId`, статус читается через `GET /api/tasks/{id}`. Стриминга ответа по токенам нет. См. [api-contract.md](api-contract.md#чат-ассистента-bil-36-bil-37).
- Где именно живёт генератор кода (`AppDocument` → файлы Expo-проекта) — в прототипе это чистая TS-функция (string-templating, без AST), которая вызывается и в браузере (для живой панели кода/файлов в редакторе), и на сервере (для zip-экспорта). Такая же двойная потребность (клиент + сервер) сохранится и у нас — решить, дублировать ли генератор на Python для бэка или гонять через внутренний вызов.
- Авторизация/пользователи — в ТЗ не упомянуты вообще, в прототипе тоже нет (фейковый заголовок пользователя).
- Хранилище загружаемых файлов/изображений — не специфицировано, в прототипе тоже только метаданные без реальной загрузки.
- ~~Генерация `AppDocument` из промпта~~ — закрыто в BIL-15: вместо прототипного keyword-regex выбора из 5 шаблонов бэкенд генерирует документ LLM через RouterAI, без фоллбэка на шаблоны. См. [api-contract.md](api-contract.md#асинхронная-генерация-приложения).
